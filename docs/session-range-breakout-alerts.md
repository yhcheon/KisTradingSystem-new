# 주간·야간장 시초 레인지 돌파 경보 설계

- 상태: 구현 진행 중
- 작성일: 2026-11-18
- 대상: KOSPI200 정규선물
- 범위: 주간/야간 세션별 기준 고가·저가 수집, 돌파 경보, 차트 수평선

## 1. 목표

각 거래 세션의 시작 구간에서 형성된 고가와 저가를 실시간 체결 틱으로 기록하고, 기준 구간 종료 후 가격이 기준 고가를 상향 돌파하거나 기준 저가를 하향 이탈하면 브라우저 팝업과 음성으로 한 번씩 알린다.

미니선물은 정규선물과 유사하게 움직이므로 별도 감시하지 않는다. 기존 시세 카드와 차트 데이터 흐름은 유지하고, 경보 기능은 독립 모듈로 구현한다.

## 2. 확정 요구사항

| 항목 | 주간장 | 야간장 |
|---|---|---|
| 기준 수집 구간 | 08:45:00 이상 ~ 09:30:00 미만 | 18:00:00 이상 ~ 18:45:00 미만 |
| 돌파 감시 시작 | 09:30:00 | 18:45:00 |
| 감시 종료 | 주간 세션 종료까지 | 야간 세션 종료까지 |
| 감시 종목 | 정규선물 최근월물 | 정규선물 최근월물 |
| 가격 입력 | KIS 실시간 체결 틱 | KIS 실시간 체결 틱 |
| 돌파 조건 | 기준 고가보다 높은 체결가 | 기준 고가보다 높은 체결가 |
| 이탈 조건 | 기준 저가보다 낮은 체결가 | 기준 저가보다 낮은 체결가 |
| 알림 | 팝업 + 음성 | 팝업 + 음성 |
| 반복 제한 | 세션별 고가/저가 각각 최초 1회 | 세션별 고가/저가 각각 최초 1회 |
| 차트 | 기준 고가/저가 수평선 | 기준 고가/저가 수평선 |

알림 문구:
- 고가 돌파: “시세가 고가 돌파 했습니다. 숏 포지션은 위험 관리 하세요.”
- 저가 이탈: “시세가 저가를 깼습니다. 롱 포지션은 위험 관리 하세요.”

고가 돌파와 저가 이탈은 서로 독립적이다. 한쪽 알림이 발생해도 반대쪽 알림은 별도로 한 번 발생할 수 있다.

## 3. 세션 수명주기

### 주간장
1. 백엔드의 KIS 실시간 시세 구독이 08:45 전에 준비되어 있어야 한다.
2. 08:45:00부터 09:29:59까지 정규선물 틱의 최고가/최저가를 누적한다.
3. 09:30:00부터 기준 가격을 고정하고 돌파/이탈을 감시한다.
4. 주간 세션이 끝날 때까지 감시한다.

### 야간장
1. 백엔드의 KIS 실시간 시세 구독이 18:00 전에 준비되어 있어야 한다.
2. 18:00:00부터 18:44:59까지 정규선물 틱의 최고가/최저가를 누적한다.
3. 18:45:00부터 기준 가격을 고정하고 돌파/이탈을 감시한다.
4. 야간 세션이 끝날 때까지 감시한다. 자정 이후 KIS가 전달하는 영업일 기준 날짜/확장 시각을 그대로 사용해 동일 세션으로 처리한다.

## 4. 늦은 서버 시작 및 데이터 누락 정책

과거 데이터 조회를 통한 보정/복구는 하지 않는다.

- KIS 실시간 수집이 주간 기준 구간 시작(08:45) 이후에 준비되면 그날 주간 경보는 비활성화한다.
- KIS 실시간 수집이 야간 기준 구간 시작(18:00) 이후에 준비되면 그날 야간 경보는 비활성화한다.
- 기준 구간 중 틱이 전혀 수신되지 않아 고가/저가를 만들 수 없으면 해당 세션 경보를 비활성화한다.
- 기준 가격이 정상적으로 만들어지지 않은 세션은 임의 가격으로 경보를 내지 않는다.
- 정상 운영은 주간 08:30, 야간 17:30 이전 서비스 자동 실행을 전제로 한다.

세션 준비 여부는 KIS WebSocket 수집 모듈이 시작되는 시각을 기준으로 판단한다. 브라우저 접속 시각은 기준 가격 수집 자격에 영향을 주지 않는다. 브라우저가 늦게 접속해도 서버가 만든 현재 세션 상태를 초기 메시지로 전달한다.

## 5. 데이터 및 처리 구조

- 서버의 세션 감시기가 단일 기준 상태를 관리한다. 브라우저별로 기준 가격을 다시 계산하지 않는다.
- 감시 대상 코드는 백엔드가 선택한 정규선물 최근월물 코드 하나다.
- KIS 실시간 틱을 기존 CandleStore에 반영하는 흐름과 별도로 세션 감시기에 전달한다.
- 감시기는 세션별 거래일, 기준 고가/저가, 준비 상태, 고가 알림 여부, 저가 알림 여부를 보유한다.
- KIS 틱을 받은 서버는 감시 상태를 갱신한 후 기존 브라우저 WebSocket broadcast에 전달한다.
- 브라우저 WebSocket 연결 직후 세션 상태 snapshot을 전달하고, 이후 실시간 틱 메시지에 최신 세션 상태와 새로 발생한 경보 이벤트를 포함한다.
- 주간/야간 상태는 서로 독립적으로 관리한다. 거래일이 바뀌면 해당 세션 상태와 알림 여부를 초기화한다.
- 서버 메모리 상태이며 DB/Redis에 영속 저장하지 않는다. 서버 재시작 시 당일 세션도 새로 시작하며, 이미 기준 구간이 지난 세션은 비활성화한다.

## 6. 차트 표시 및 사용자 알림

- 정규선물 차트에 기준 고가/저가를 수평 가격선으로 표시하고 선 옆에 “주간 고가”, “주간 저가”, “야간 고가”, “야간 저가” 및 가격을 표시한다.
- 미니선물 차트를 선택한 동안에는 이 정규선물 기준선을 표시하지 않는다.
- 기준 구간 수집 중에는 수집 상태와 잠정 고가/저가를 표시한다. 구간 종료 후 기준 가격을 고정한다.
- 서버에서 새 경보 이벤트가 도착하면 팝업을 표시하고 브라우저 음성 합성으로 확정 문구를 읽는다.
- 새로 연결된 브라우저에는 현재 상태만 전달한다. 이미 발생한 경보를 과거 이벤트로 재생하지 않는다.

## 7. 중복 알림 규칙

각 세션은 `high_alerted`, `low_alerted`를 독립적으로 관리한다.
- 기준 고가를 처음 상향 돌파하면 고가 경보를 발생시키고 `high_alerted`를 설정한다.
- 같은 세션에서 이후 고가를 재돌파해도 추가 경보는 발생시키지 않는다.
- 기준 저가를 처음 하향 이탈하면 저가 경보를 발생시키고 `low_alerted`를 설정한다.
- 같은 세션에서 이후 저가를 재이탈해도 추가 경보는 발생시키지 않는다.
- 기준선 안으로 복귀하더라도 알림 상태를 되돌리지 않는다.
- 다음 세션 거래일에만 초기화한다.

## 8. 테스트 기준

백엔드 단위 테스트:
- 세션별 기준 구간 시작/종료 경계 시각
- 기준 구간 내 고가/저가 누적 및 종료 후 기준 고정
- 기준 고가보다 높은 첫 틱에서 고가 경보 1회 발생
- 기준 저가보다 낮은 첫 틱에서 저가 경보 1회 발생
- 반복 돌파/이탈 시 중복 경보 없음
- 주간/야간 독립 상태 및 거래일 변경 초기화
- 서버/수집기 시작 시각이 기준 구간 이후면 세션 비활성화
- 미니선물 코드의 틱은 무시

프론트엔드 확인:
- WebSocket 초기 snapshot으로 기준선이 복원됨
- 정규선물 차트에 4개 세션 가격선 중 활성 세션 선이 표시됨
- 새 경보 이벤트에 팝업/음성이 한 번 표시됨
- 이미 발생한 이벤트가 재접속 시 다시 재생되지 않음
- 미니선물 차트에는 정규선물 기준선이 표시되지 않음

## 9. 구현 범위에서 제외

- KIS 과거 틱/분봉을 통한 기준 가격 복구
- 미니선물 별도 경보
- 돌파 폭을 2틱/3틱으로 설정하는 옵션
- 기준선 복귀 후 재알림
- 사용자별 경보 설정/음소거 UI
- 데이터베이스 영속 저장 및 과거 경보 이력
